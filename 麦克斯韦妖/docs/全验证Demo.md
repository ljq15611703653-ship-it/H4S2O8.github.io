# 《麦克斯韦妖的燃烧水》全验证 Demo

## 目标

制作一个 Godot 4.7.1 的横版物理解谜 Web Demo。玩家控制一个妖怪，通过让物品直接接触并手动转移物性、利用自动接触反应和动态碰撞体，到达高处出口并清空门前阻挡区。

通关只检查世界最终状态，不检查操作历史：

1. 门前阻挡区内没有重物；
2. 玩家进入出口区域。

## 统一物品模型

每个可交互对象由以下层组成：

- 基底身份：石、木、水、玻璃、机器等；普通物性变化不会改写身份。
- 五条可转移物性轴：温度、燃烧性、冻结性、重量、形变，值均为 `-1 / 0 / +1`。
- 过程状态：燃烧、冻结；过程不能像普通物性一样直接复制。
- 物态：第一版只实现固态和液态，不实现气态、蒸发和升华。
- 结构状态：完整、破碎；可破坏性和绝对不可破坏不是可转移物性。
- 功能状态：熔炉、冷柜、容器、玻璃闸门等功能；破碎后功能失效，基底和普通物性保留。
- 形状状态：视觉轮廓、物理碰撞体、质量中心和可通行区域必须同步更新。

## 转移

- 只有直接接触的两个不同物品可以转移。
- 五条物性轴适用于所有可交互物品，不按基底设置“不可转移的固有属性”；石、木、水和机器都能获得黏塑、轻、可燃等状态。
- 五条物性轴适用于所有可交互物品，不按基底设置“不可转移的固有属性”；石、木、水和机器都能获得黏塑、轻、可燃等状态。
- 玩家必须手动选择轴和方向。
- 转移一个单位，不复制；源和目标同时改变。
- 数值不能越过 `-1` 或 `+1`。
- 重物把重性转移给普通物后，原物变普通，接收物变重。
- 轻物持续连接并牵引重物时，只把重物的“有效重量”临时降为普通；连接断开后恢复。
- 妖怪不能徒手抓取重、冷、烫、燃烧、结冰或锚定在场景中的固定装置；手中物因转移/接触反应进入这些状态时立即脱手。固定装置仍可参与接触转移。
- 手持物仍与地形和其他物品保持真实碰撞，但手持期间忽略与持有者本人的碰撞，避免抓取力把角色楔进墙；放下后恢复。
- 手持物必须在可通行空间内稳定跟随手部，不能出现 HUD 仍显示持有、实体却留在远处的“无限长手臂”。物品被狭缝或墙体阻挡、与手部距离超过 110 像素时，必须自动脱手并留在阻挡处。
- 液态水可以获得可燃和烫，并在保持液体碰撞与流动/合并规则的同时燃烧，形成“流动的火”。
- 液体不使用晃动轮廓或高光冒充流动。一份液体用守恒网格记录体积，根据重力、容器和障碍持续重排占用格，并从占用格重建绘制轮廓与接触碰撞。
- 流体实现只检查 `phase == liquid`，水、油及燃烧液体复用同一套物理。连通的一团液体共享五轴与过程状态；流散成多个不连通区域后自动裂为多份独立液体，重新接触且状态完全一致时再合并。
- 水初始装在有真实底板、侧壁和可破坏出口的浴缸里，不直接生成在地面上。

## 接触反应

- 烫接触可燃物：立即燃烧。
- 燃烧物：每个接触步持续输出一个烫单位；直接接触物由冷升为常温、或由常温升为烫，同时点燃可燃物。燃烧源本身不因输出而失去烫。
- 灭火物接触燃烧物：立即停止燃烧。
- 冷接触可冻结物：立即冻结。
- 阻止结冰物接触冻结物：接触期间立即解冻；一旦分开，若原物仍同时为“冷 + 可冻结”，立即重新结冰。
- 永久融化必须先让物体不再同时满足“冷 + 可冻结”，不能只删除结冰过程。
- 正负温度接触后归中；过程后果根据基底和当前结构保留。
- 温度正负抵消优先于新过程触发：冷且可燃的目标先被烫加热到常温，本接触步不燃烧；烫且可冻结的目标先被冷却到常温，本接触步不结冰。持续火源可在后续接触步继续加热并点燃。
- 燃烧过程可以自动加热接触物，不要求玩家手动抽取；普通液态水接触燃烧物后会被加热。
- 非燃烧的液态水在直接接触期间压住火焰，但不删除原物的烫和可燃：普通水离开后原物立即复燃；冷水会同时消耗烫，离开后不会凭空复燃。
- 可燃水被点燃后成为燃烧水，不再以“非燃烧水”压火，而会继续向接触物产烫和传火。
- 同种液体的不同状态先反应，反应后全部物性和过程相同才合并；例如烫水和冷水先同时归中，再合并为常温水。

## 物态、破坏和合并

- 固体永不自动合并。
- 只有基底、液态、全部物性和过程状态完全一致的液体在接触后合并。
- 液体按重力沿可通行碰撞空间向低处聚拢。
- 水冻结后成为固态刚体；碎冰仍是多个固体，不合并；解冻后变为液体，满足条件才合并。
- 冻结石头打碎并解冻后仍是碎石，不会变成液体。
- 木结构燃烧后可以烧穿：燃烧过程仍在，但碰撞体出现真实缺口。
- 玻璃破碎后挡水功能和原碰撞体失效，产生简化碎片体。

## 全验证关卡

场景分为低层工作间、人通道、货物通道和高层出口：

- 玩家通过弹性物形成的弹跳面到达原本不可达的平台；弹性物不用于拖拽重物。
- 轻物会持续上浮，因此初始放在下方开口、顶部和两侧封闭的捕轻笼中；玩家必须进入人通道后从下方取出，不能让关键物品飞出关卡。
- 货物不能跟随玩家通过人通道，必须由可翻转地板、斜坡、冰支撑或烧穿结构送往高层。
- 出口门和外框绝对不可破坏，位于高处。
- 门前初始有重物；门槛下方有下沉卡槽。
- 普通接收物在门前获得重性后，会压下门槛地板并卡在门口，仍然挡门；玩家必须预先改变地板、把接收物送入侧槽、用轻物临时减重，或采用其他路线。
- 组合原理不作为路边关卡提示；按 `C` 打开“实验图鉴”查阅已经验证的材料组合。图鉴解释物理结果，不给出固定通关摆法。

## 必须通过的路线

1. **重量转移路线**：把普通接收物经货物通道送入侧槽，再与门前重物直接接触并转移重性；新重物不挡门。
2. **轻物牵引路线**：取得轻物并用黏塑物建立持续连接，使门前重物有效重量变普通后推离。
3. **地形路线**：不转移重量，通过烧穿木支撑或改变铰接地板坡度，让重物依靠重力滑入侧坑。
4. **冰支撑路线**：释放水、冻结成固态支撑改变地板角度，随后按需要打碎或解冻；液体重新聚拢并合并。

## 自动验收

- 五条轴的所有合法单步转移与边界拒绝。
- 所有自动接触反应的正向和边界案例。
- 每种功能物品与每种状态对象的两两接触矩阵，无异常、无顺序依赖。
- 燃烧、冻结、解冻、破碎、烧穿、固液切换、液体合并后的碰撞体与视觉形状一致。
- 轻物连接建立和断开后的有效重量恢复。
- 普通接收物变重后触发卡槽，不能误判通关。
- 四条通关路线分别从初始快照运行到通关。
- Web 导出在 HTTP 服务和 GitHub Pages 地址中加载、接收输入、完成通关。

## 黑盒与破坏性验收

- 四条规定路线必须分别从全新 Web 页面开始，只通过玩家键盘输入完成；不允许测试代码直接修改物品坐标、属性或门状态。
- 黑盒成功以画面出现“实验完成”和浏览器标题更新为准，并保留操作序列与末帧截图。
- 正常路线通过后，对所有初始可抓物逐一尝试“沿人通道直接带到门边或侧槽，再一次转移重性”的莽解。
- 尝试夹带货物穿人通道、卡门区边界、碰撞挤墙、抓取穿墙、跳过货运末段和最少操作推挤。
- 若任意普通物无需解决货运/地形约束即可被手持送入安全侧槽并转移重性，则判定关卡设计失败，即使状态目标能正确通关。
- 修复不得给特定物品添加“不能接收重性”等例外；所有可交互物仍可转移五轴。应通过碰撞地形和人/货路线分离，让安全侧槽只能由真实货运过程送入物品。
- 破坏性组合测试必须主动寻找天马行空的链式状态：燃烧液体再冷却/冻结、轻液体、黏与弹性的相反转移、临时灭火后复燃、冻结后破碎再融化、连接链中途转移轻重、同物质不同状态先反应再判断合并。
- 意外解法本身可以成立，但每一步必须服从同一套三值守恒、接触反应、碰撞体更新、相态与结构规则；任何凭空复制/丢失属性、状态与形状不一致、合并吞物或连接残留都判定为 bug。
